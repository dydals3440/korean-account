# 점수와 신뢰도

`detect`가 후보를 고르고 순서를 정하는 규칙입니다. 모든 값은 `src/core/detector/`의 구현과 `src/builtin/evaluation.spec.ts`의 평가 테스트가 고정합니다.

## 처리 순서

1. **정규화**: 입력에서 숫자만 남깁니다. 전각 숫자(`０–９`)도 ASCII 숫자로 셉니다. 숫자가 없으면 빈 배열을 돌려줍니다.
2. **길이 색인**: 입력 자릿수와 ±1자리 차이 안에 있는 패턴을 가진 기관만 채점합니다.
3. **패턴 채점**: 기관의 패턴마다 점수를 매기고 가장 높은 패턴 하나를 고릅니다. 동점이면 먼저 선언된 패턴이 이깁니다.
4. **분기 규칙**: 고른 패턴에 `branchRule`이 있으면 기관을 재배정하거나 계좌 종류를 바꿉니다(예: 수협은행과 수협중앙회, 농협 13자리의 계좌구분).
5. **신뢰도**: 점수와 근거로 `high`·`medium`·`low`를 정합니다.
6. **정렬과 정리**: 신뢰도 등급 → 점수 → 사전확률 → 계좌 종류 순으로 정렬합니다. 1순위가 `high`나 `medium`이면 `low` 후보를 버립니다.
7. **모호성**: 같은 신뢰도 등급에 다른 기관이 있으면 `ambiguous: true`입니다.
8. **옵션**: `categories`·`kinds`·`include`·`exclude`·`minScore`로 거르고 `limit`만큼 자릅니다. 거른 기관도 `ambiguous` 판정에는 들어갑니다.

## 패턴 점수

| 항목              | 기본 가중치 | 조건                                                                      |
| ----------------- | ----------- | ------------------------------------------------------------------------- |
| `lengthExact`     | 3           | 입력 자릿수가 패턴과 같음                                                 |
| `lengthNear`      | 1           | 입력 자릿수가 패턴과 1자리 차이                                           |
| `identifierMatch` | 4           | 식별 자리(지점·상품 코드 등)가 `identifiers`나 `identifierRange`에 들어감 |
| `subjectMatch`    | 3           | 과목 자리가 `subjects`의 코드와 같음                                      |
| `additionalRule`  | 1           | 패턴의 추가 규칙 하나를 통과할 때마다                                     |
| `globalRule`      | 1           | detector 전역 규칙 하나를 통과할 때마다                                   |
| `branchRuleMatch` | 2           | 분기 규칙이 근거 있는 후보에 적용됨                                       |
| `kindNewBonus`    | 0           | `kind: "new"` 패턴 가산점(기본 꺼짐)                                      |

식별자·과목 점수는 코드 길이만큼 늘어납니다. 3자리 식별자는 `4 + (3 − 1) = 6`점, 3자리 과목은 `3 + 2 = 5`점입니다. 입력이 패턴보다 짧으면(입력 중) 이 두 점수를 반으로 내림하고, 패턴보다 길면 주지 않습니다.

식별자와 과목이 같은 숫자를 가리키면(자리가 일부라도 겹치면) 큰 점수 하나만 셉니다. 같은 숫자를 두 번 세지 않기 위해서입니다.

추가 규칙(`additionalRules`)은 입력이 패턴 길이 ±1자리일 때만 검사합니다. 하나라도 실패하면 그 패턴은 일치하지 않습니다.

가중치는 `createDetector(institutions, { scoring: { identifierMatch: 6 } })`처럼 바꿀 수 있습니다. 값은 0 이상의 유한한 수여야 하고, 아니면 `RangeError`를 던집니다.

### 예시: `110-436-387740`

신한은행 12자리 패턴(`XXX-XXX-XXXXXX`)은 앞 3자리가 식별 자리이자 과목 자리입니다.

| 항목                    | 점수  |
| ----------------------- | ----- |
| 길이 일치               | 3     |
| 식별자 `110`(3자리)     | 6     |
| 과목 `110` 저축예금     | 5     |
| 같은 자리이므로 큰 값만 | 6     |
| **합계**                | **9** |

우체국·신협의 12자리 패턴도 같은 방식으로 9점이 되어 세 기관이 `high`로 동점입니다. 그래서 세 후보 모두 `ambiguous: true`이고, 순서는 사전확률이 정합니다.

## 신뢰도

| 등급     | 조건                                           |
| -------- | ---------------------------------------------- |
| `high`   | 점수 7 이상이고 근거가 있음                    |
| `medium` | 점수 4 이상 7 미만이고 근거가 있음             |
| `low`    | 점수 4 미만이거나, 점수와 관계없이 근거가 없음 |

**근거**는 다음 셋 중 하나입니다. 길이와 추가 규칙만 맞은 후보는 근거가 없습니다.

- 식별자가 등록된 값과 일치
- 과목 코드가 등록된 값과 일치
- "그 외" 분기(`isFallback`)가 아닌 분기 규칙의 조건이 성립

기준 7·4는 기본 가중치에 맞춰져 있습니다. 가중치를 바꾸면 같은 번호의 등급도 바뀔 수 있습니다.

## 정렬과 모호성

정렬 키는 신뢰도 등급, 점수, 사전확률([`prevalence`](./api.md#prevalence)), 계좌 종류(`new` → `old` → `virtual` → `lifetime` → `incoming-only` → `merged-legacy`) 순입니다. 등급을 먼저 보기 때문에 근거 없는 `low` 후보는 점수가 높아도 근거 있는 후보를 앞지르지 못합니다.

사전확률은 기관의 `priority`가 있으면 그 값을 쓰고, 없으면 `userBaseMillions`(이용자 수, 백만 명)에 기관 분류별 계수(은행 1, 비은행 0.6, 증권 0.25, 결제원 0)를 곱합니다. 점수에는 더하지 않고 동점일 때 순서만 정합니다.

`ambiguous`는 입력 자체의 성질입니다. 옵션으로 경쟁 기관을 숨겨도 그대로 `true`입니다. 앱이 신한은행만 지원하더라도 `110-436-387740`이 우체국 계좌일 수 있다는 사실은 바뀌지 않기 때문입니다.

## 평가 지표

2026-11-14에 내장 레지스트리와 기본 가중치로 측정했습니다. 평가 테스트가 아래 하한을 래칫으로 고정합니다.

| 평가                                                   | 표본                                  | 결과                                        |
| ------------------------------------------------------ | ------------------------------------- | ------------------------------------------- |
| 패턴 표본에서 정답 기관이 최상위 신뢰도 등급 안에 있음 | 식별자·과목이 있는 99개 패턴, 1,980건 | 100%                                        |
| 위와 같은 표본에서 정답 기관이 단독 1순위              | 1,980건                               | 62% (나머지는 같은 체계를 쓰는 기관과 동점) |
| 대표 번호의 1순위 적중                                 | fixture 53건                          | 100% (모두 `high`, 이 중 60%는 `ambiguous`) |
| 근거 없이 `medium` 이상이 나온 결과                    | 무작위 7–14자리 3,000건               | 0건                                         |

정리하면, 정답은 거의 항상 첫 신뢰도 등급 안에 있지만 그 등급에 여러 기관이 함께 있는 경우가 많습니다. UI에서는 `ambiguous`일 때 후보를 보여 주고 사용자에게 고르게 하세요.

무작위 숫자도 절반 가까이는 어떤 기관의 형식에 `high`로 맞습니다. 3자리 식별자 하나가 숫자 공간의 상당 부분을 덮기 때문입니다. 높은 신뢰도는 "이 기관의 형식과 맞다"는 뜻이지 "실제 계좌다"라는 뜻이 아닙니다.
